## Summary
`/actuator/info` reports `"dirty": false` when the working tree has new untracked source files, so the flag can say the commit id fully describes the build when it does not.

## Steps to reproduce
1. Fresh clone of the branch, `cd Backend/tieyoh-api`.
2. `echo x > newfile.txt` (untracked, not ignored); `./mvnw -q clean package -DskipTests`.
3. `grep dirty target/classes/git.properties`.
4. Modify a tracked file (`echo "<!-- x -->" >> pom.xml`), rebuild, grep again.

## Expected result
Per Decision 4, dirty = "build had uncommitted changes" (arguably including new untracked source files).

## Actual result
Untracked file: `git.dirty=false`. Tracked modification: `git.dirty=true`. (Already flagged by the developer; this is the git-commit-id plugin default, no `<excludeProperties>`/untracked option set.)

## Evidence
```
untracked: git.dirty=false
tracked-mod: git.dirty=true
```
Low: the REQ does not define whether untracked files count, nothing sensitive leaks, and tracked changes are detected. Recommend Hany accepts or asks for a one-line decision.

## Developer fix notes
_Mississippi, 2026-10-14, commit 1aba418 on feature/REQ-001-backend-build-info_

- **Root cause:** git-commit-id-maven-plugin (JGit) ignores untracked files when computing `git.dirty`.
- **Change:** git.properties is now generated by the git CLI (see DEF-003). `git.dirty` = `git --no-optional-locks status --porcelain --untracked-files=normal` is non-empty. This counts tracked changes (staged or unstaged) and untracked files that are not gitignored, anywhere in the repository. Ignored files such as `target/` don't count.
- **Behavior note:** builds from Hany's main checkout will now report `dirty: true` while it has untracked, non-ignored folders such as `tieyoh-test/` and `.claude/worktrees/` (and `.DS_Store` files, which aren't ignored either). That's correct under this definition. To get `dirty: false` there, add those paths to `.gitignore` or `.git/info/exclude`, or build from a clean clone.
- **Test added:** `GitPropertiesMatchCheckoutTests.dirtyMatchesWorkingTreeIncludingUntrackedFiles`, which compares `git.dirty` with git status of the checkout under test.
- **Verified manually** in a scratch worktree: clean gives false, untracked file gives true, ignored file only gives false, staged change gives true.
